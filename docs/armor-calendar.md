# 护甲制作与活动日历

## 使用

顶部导航切换世界地图、护甲制作和活动日历。角色管理及数据备份在所有页面共用；链接保存页面、筛选、制作方案、勾选部位和日历日期，不包含个人计划或完成记录。

护甲覆盖十职业及可制造的通用部位，当前为 298 种外观、1,057 份制作方案、52 位制作商、33 种材料和 596 张男女预览图。同一外观的不同篇章、防御值、NPC 和部分部位供应分别保留。未提供的部位不参与合计；圣言使瓦比头饰的单件费用与身体部位不同。只计算材料数量与 NPC 固定费用，不计算库存、交易价格、符文、徽记或染料。

选择制作方案和部位后，可以按角色保存多个具名计划，在下方逐件勾选已制作，并查看整份计划及剩余需求。删除角色也会删除其计划。收藏家兑换、英雄护甲、服装及节庆帽不在制作目录中，七个仅有起始／兑换获取方式的外观明确列在覆盖报告中。

日历包含四类战承任务、旅者尼古拉斯及 PvE/PvP 每周奖励，共 430 条活动。支持名称、Boss、区域或兑换物搜索，点击下一次出现可直接跳转日程。详情保留目标、奖励、领取／交付地点、限制及来源；部分资料为英文原文。关联现有区域时可以返回地图档案，位置未确认时不推测绘制标记。

默认北京时间，另可选择设备时区或 UTC。战承每天 UTC 16:00 重置（北京时间次日 00:00）；旅者与每周奖励每周一 UTC 15:00 更新（北京时间周一 23:00）。日期格按开始时间归档，每周活动也显示当天仍生效的前一轮；“当前生效”按真实时间区间判断。历史日期选择范围为 2013-05-13 至 2100-12-31，未来为已核验常规周期的预测，不包括节庆叠加或临时调整。

战承记录绑定角色、任务及该次轮换开始时间，可补记过去的活动，未来不能提前完成。战斗类可重复，勾选只表示本轮做过；每日战承清剿不影响永久区域清剿记录。旅者展示每份与五份礼物所需材料，说明每账号每周五份上限，不记录兑换次数；每周奖励也无完成按钮。

## 数据维护与核验

普通构建直接使用已提交的 `public/data/armor.json`、`calendar.json` 和图片，不联网。新资料独立于旧 TXT 转换流程。更新 Wiki 内容时，通过 `WIKI_PROXY` 指定系统代理：

```powershell
$env:WIKI_PROXY='http://127.0.0.1:7890'
npm.cmd run wiki:fetch:features
npm.cmd run wiki:compile:features
npm.cmd run wiki:images:armor
npm.cmd run wiki:compile:features
node scripts/wiki/audit-armor.mjs --write
node scripts/wiki/audit-references.mjs --remote
npm.cmd run build
```

抓取命令保留已有快照；有意更新修订时需先用现有 `fetch.mjs titles <标题清单> --refresh` 刷新目标来源，再重新编译和审计。图片下载记录文件名、来源页面、原图 SHA-1 和时间；生成的 WebP 与图片清单均需提交。新增数据版本由编译脚本显式维护，不按每次构建时间变动。

护甲发现范围与排除项见 `data/wiki/armor-coverage.json`。表格解析保留 rowspan、colspan、空部位、跨篇章材料变化、独立护甲与不同部位价格；未知格式中止编译，避免发布半份资料。654 行来源提供独立总计栏，金币与材料均已逐行对照。

来源有两处已审查的算术冲突：Ranger Drakescale armor 在 Hanita / Alemeth 的 AR 55 配方总计写为 600 金币，但四件均标价 200；Armorer 总表同样列单件 200。应用按 800 合计，并在配方说明保留冲突；原始快照不修改。审查结果见 `data/wiki/armor-totals-audit.json`。

轮换顺序直接读取 Wiki 数据模板：每日周期为 69 / 66 / 28 / 136 天，旅者 137 周，PvE/PvP 奖励分别 9 / 6 周。`data/wiki/calendar-fixtures.json` 保存 Wiki 服务器在固定日期及重置前后的模板展开结果，用于独立对照。所有新引用纳入原有修订和 SHA-1 审计。

## 本地数据、备份与离线

IndexedDB `mappingout` 升级到版本 2，旧角色、进度、笔记与偏好在升级事务中保留。新增护甲计划及活动记录仍使用同一存储接口，在读写事务中基于最新值更新，支持跨标签页同步。旧版本页面不能继续用数据库版本 1 写入；请刷新旧标签页。

导出备份为 `mappingout-backup` v2；支持 v1 输入并显示迁移预览，v1 没有的新功能记录初始化为空。v2 导入校验角色引用、重复计划、部位集合、时间及重复轮换记录；失败不替换原数据。导入仍是整体替换而非合并。

新页面代码和两份资料随应用预缓存，预览图访问后缓存。首次联网加载并完成缓存后，日历继续根据设备时间离线计算。切换到未访问的护甲时，离线可能缺图，配方和计算仍可用。

数据库升级后，回滚应选择同样支持数据库 v2 的应用版本。旧版 v1 应用不能读取升级后的数据库或 v2 备份；不要通过清理网站数据处理回滚。需要代码回退时保留本次存储兼容层，并先导出备份。
