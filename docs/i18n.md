# 客户端语言与离线字体

简体中文（默认）与 English 使用独立界面字典和资料语言包。设备语言保存在
`mappingout.locale`，不写入个人数据备份。切换语言不改变筛选 ID、坐标、角色记录、
护甲制作数量或日历显示时区。搜索同时接受两种语言的名称。

英文以引用修订的 Guild Wars Wiki 为基准；中文是这份英文的译文。
`public/data/{catalog,armor,calendar,quests,skills}.json` 保留结构化事实、引用和旧资料，不能把其中的
旧中文当作英文来源。语言包按实体 ID 和字段路径覆盖显示文字，并同时绑定原始数据、
英文正文和英文来源基准的 SHA-256。缺失、过期或两种语言的英文基准不一致时会报错。
来源与历史资料默认折叠。

任务攻略按安全内容块投影，奖励数字、关系 ID、模式、图像来源和个人进度不翻译。
`data/i18n/quest-translations.json` 保存绑定英文哈希的机器辅助中文初稿。
任务页提示待校订状态，并提供英文原文切换。采集与维护步骤见 [任务攻略](quest-guides.md)。

职业技能为第五套独立语言资料。
`data/i18n/skill-translations.json` 保存 13,492 条独立机器辅助译文。
技能正文的成长占位符和数字在翻译时受到保护，丢失时重试并校验。
技能投影保持资源、逐级效果、来源、获取和版本身份不变。
名称及正文索引同时包含两种语言，不随当前界面语言缩小搜索范围。
技能页保留待校订提示及英文原文切换；维护步骤见 [职业技能](skills.md)。

`src/i18n/content-fields.ts` 是显示文字字段的清单；ID、坐标、材料数量、轮换周期、
来源 URL/revid 与旧版原文都不翻译。用户的角色名、笔记、自定义计划名也不翻译。

维护命令：

- `npm run i18n:audit`：从引用快照重新提取英文、比对事实并生成准确性问题清单。
- `npm run i18n:compile`：用英文基准和已有中文稿重新编译离线语言包，不反译英文、不联网机翻。
- `WIKI_PROXY=http://127.0.0.1:7890 node scripts/i18n/check-wiki-revisions.mjs`：只读检查 Wiki 当前修订。
  PowerShell 请先设置 `$env:WIKI_PROXY='http://127.0.0.1:7890'`，再运行 Node 命令。
- `npm run validate:i18n`：检查字典、占位符、资料覆盖率与字体文件。
- `npm run check:release`：严格检查，并应用绑定版本和资料指纹的已记录发布例外。
- `npm run check:release:strict`：不应用例外，输出全部待复核项和字体分发授权问题。
- `node scripts/i18n/review-report.mjs`：生成按相同译文合并的待复核清单
  `data/i18n/review-queue.json`，附原文、译文、引用字段及两种哈希。

`data/i18n/baseline/` 区分 Wiki 英文原文、结构化事实的固定呈现方式，以及应用自身的说明。
每个已确定的英文来源记录正文哈希和页面修订信息。不能确认来源的英文草稿单独列入
`unverifiedFields`，保留待校订状态；不会把它们当作其他译文的基准。

旧机器稿在 `data/i18n/drafts.json` 中保留，不冒充校订结果。人工复核记录改为 v2：
`data/i18n/review.json` 中每个 `语言/数据集/字段key` 必须记录 `englishHash`、
`evidenceHash`、`translationHash` 和 `reviewer`。英文、引用修订或中文变化均使旧复核失效。
数值签名保留正负号、百分比、范围、重复次数和顺序；语序变化等合理差异需要明确的
`numericReview` 说明，乱码不能豁免。数值相同不能代替语义校订。

技能说明的手工译文在 `scripts/i18n/reviewed-skills.mjs`，同时以
`data/i18n/skill-review-sources.json` 固定英文哈希和 Wiki 修订。更换修订时必须重新读过
对应差异，不能只按同名技能自动批准旧译文。旅者物品译名采用单独校订的英文词表，
数量由 Wiki 轮换事实生成，避免另写一份数量。

已校订的 20 个地区和 4 个篇章英文标签从旧 overrides 中迁入英文基准。
新的英文应用说明可以写入 `data/i18n/english-reviews.json`，按 `数据集/字段key` 指定
`sourceHash`、`text`、`reviewer` 和来源类型。不得在这里批准未经 Wiki 核实的反译游戏事实。

离线模型仅用于维护时生成机器草稿，不随客户端分发，也不会在运行时翻译资料或发送
用户数据。使用的 Argos OPUS-MT 1.9 模型为 CC-BY 4.0，作者 Jörg Tiedemann 和
Santhosh Thottingal，论文 “OPUS-MT — Building open translation services for the World”，
EAMT 2020。维护环境需自行安装 `ctranslate2`、`sentencepiece` 和模型；可重复编译
已提交的语言包完全不需要这些工具或网络。

## 当前验证状态

2026-11-17 的技能实现包含五套双语资料，覆盖 267,604 个字段位置，完整性错误为 0。
其中 131,779 项待人工复核，1,988 项有数值审查标记，14,086 项含中英文混合，
2,026 项英文仍待来源确认。这些数量覆盖全应用，不代表技能译文已完成人工校订。
技能资料变化没有扩大 1.2.0 的旧发布例外。

2026-11-16 的任务攻略历史验收包含四套双语资料，覆盖 179,152 个字段位置，完整性错误为 0。
其中 87,553 项待人工复核，1,638 项有数值审查标记，2,026 项英文仍待来源确认。
这些计数覆盖全应用，不能当作任务译文已完成校订。

1.2.0 历史发布时，资料语言包覆盖 105,492 个字段位置，缺失字段为 0。
**1.2.0 按用户明确要求发布，但资料校订尚未完成。** 仍有机器草稿、数值／标记
待核对项和中文字段中的未译拉丁词；严格检查会输出精确数量。字段已填满不能代替翻译质量达标。
本版本的 `data/i18n/release-exception.json` 记录已知问题和资料指纹；只允许这份资料、
这些问题和这个版本通过发布。版本、资料或问题变化均须重新评估；缺失文件、过期绑定、
失效 Wiki 核对等完整性问题始终阻止发布。此例外不代表译文已复核或字体授权已获得。
本轮核对范围、实际改正的问题和剩余校订量见 [准确性核对记录](translation-accuracy-audit.md)。

已验证语言偏好独立于备份、旧属性筛选链接兼容、双语名称搜索、即时切换时地图中心
与缩放保持、单语主名称、离线切换、Friz 和 LXGW 实际字体加载、100%／150%／200%
下的页面宽度，以及原有角色、护甲、日历和备份流程。整套资料投影的测试还逐项比较
坐标、技能数值、装备配方、来源修订、轮换周期与追踪 ID，保证事实层未被翻译修改。
Windows 上运行测试；macOS arm64 和 Windows x86 未做本次真机验证。

## 字体与发布门槛

霞鹜文楷屏幕阅读版来自 [LXGW 官方 v1.530](https://github.com/lxgw/LxgwWenKai-Screen/releases/tag/v1.530)，
保留完整原始 TTF 和 OFL 1.1 许可。没有 CDN、子集化或运行时字体下载。

Friz Quadrata Std 使用用户指定的原字体家族。用户已授权先下载用于本地实现，稍后解决许可。
[指定下载页](https://www.cufonfonts.com/font/friz-quadrata-std) 经代理仍返回 403，故从
[CDNFonts 的同名字体资源](https://fonts.cdnfonts.com/css/friz-quadrata-std) 下载原始 WOFF，
保存在本地，无运行时 CDN 请求。字体内部 name table 已核实为 `Friz Quadrata Std` /
`FrizQuadrataStd`，包含 Regular、Bold、Italic、Bold Italic。文件未经转换或改名伪装，
SHA-256 固定在清单中；版权与来源说明保存在 `fonts/friz/NOTICE.txt`。
截至本次核实，[MyFonts 官方字体页面](https://www.myfonts.com/collections/friz-quadrata-font-itc)
说明普通 Desktop 许可不允许把字体内嵌到应用或分发字体文件；其 App 许可介绍以移动应用为例，
需要权利方明确确认 Windows/macOS 离线桌面客户端的授权范围。
[Adobe 官方许可 FAQ](https://helpx.adobe.com/fonts/using/font-licensing.html)
也明确说订阅字体许可不允许内嵌移动或桌面应用，须另购适用许可。

没有把“可下载”“个人使用”或普通桌面排版许可当成客户端分发授权，也没有用近似字体替代。
字体文件和元数据已经落实，应用分发许可仍待用户补充。1.2.0 的发布例外保留
`distributionApproved: false`，没有补写或推定许可证据。用户明确要求继续发布；
本次例外及未完成校订状态同时写入版本说明，后续版本不会自动继承。
