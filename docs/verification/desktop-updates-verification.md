## 实现与检查

启动只检查一次程序更新，设置保留手动检查。下载与签名校验完成后准备兼容资料，再显示立即重启或延期选择。延期选择与完整程序包持久缓存；下次启动先恢复缓存。安装前阻止新写入、等待已接受操作完成、读取最新 IndexedDB 记录并保存本机备份。备份失败停止安装；上次安装中断停止自动重试。

## macOS 真实安装

使用 Apple Silicon 本机、独立应用标识 `dev.zhubby.mappingout.updateqa`、临时程序签名密钥、临时资源签名密钥及本地测试频道。两版 QA 应用使用 release 构建。QA 配置仅调整身份、版本、测试公钥、测试频道和构建优化；测试探针只注入 QA 前端产物。

| 场景 | 实际结果 |
|---|---|
| 立即更新 | 1.2.0 下载并验证 1.3.0，准备兼容资料；选择立即更新后替换 `.app`，重启至 1.3.0 |
| 延期后断网更新 | 1.2.0 保存延期意图与资源代号；退出并关闭测试频道后重开，使用缓存替换程序并重启至 1.3.0 |
| 离线请求边界 | 断网安装阶段未请求旧版程序更新接口；新版启动后的例行检查报告网络错误，地图与个人记录仍可用 |
| 个人数据 | 两个场景的验收角色均在新版本中保留 |
| 安装前备份 | 两个场景均存在包含对应角色的最新备份；最终回读确认立即更新角色已写入备份 |
| 安装完成状态 | 安装后的 `Info.plist` 为 1.3.0；`pending.json` 已清除；资源 `update` 固定已释放 |
| 代码对应 | QA 快照内 62 个前端与原生源码文件和最终工作树逐字节一致 |
| 正式配置 | 正式应用标识、程序公钥、程序频道及资源配置与基线一致 |

本地产物位于忽略目录 `releases/update-qa/`。`results.json` 记录重启后版本、个人记录及频道请求；`run.mjs` 为本次隔离验收脚本。QA 临时私钥在验收后删除。

原生验收预置了独立签名的兼容资源包，资源由正式原生校验路径验证；不代表首次在线资源下载验收。界面由测试探针驱动，不代表人工操作验收。此次未验证 Windows x86/x64 安装器实际运行、GitHub 正式分发、Apple Developer ID 签名或公证。
